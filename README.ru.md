# pi-codex-sale

Расширение-провайдер для [Pi](https://pi.dev), подключающее инференс-API
**Codex Sale** ([codex.sale](https://codex.sale/), `https://codex.sale/v1`).

Codex Sale говорит на OpenAI Responses API, поэтому расширение регистрирует
провайдера `codexsale`, находит доступные модели во время выполнения и
преобразует их в формат моделей Pi. О происхождении проекта см.
[Благодарности](#благодарности).

## Установка

```sh
pi install git:github.com/SustemFox/pi-codex-sale
```

или укажите Pi на локальную копию:

```sh
pi install /path/to/pi-codex-sale
```

Попробовать без установки:

```sh
pi -e git:github.com/SustemFox/pi-codex-sale
```

Затем задайте API-ключ (расширение читает `CODEXSALE_API_KEY`):

```sh
export CODEXSALE_API_KEY='ваш_ключ'
```

После этого перезапустите Pi — конфигурация читается при запуске.

Ключ выдаётся в личном кабинете на [codex.sale](https://codex.sale/) после
регистрации и пополнения баланса; там же есть инструкции по подключению на
странице [codex.sale/docs](https://codex.sale/docs).

### Конфигурация

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CODEXSALE_API_KEY` | *(нет)* | API-ключ. Обязателен. |
| `CODEXSALE_BASE_URL` | `https://codex.sale/v1` | Базовый URL API. `/v1` добавляется автоматически, если его нет. |

Для совместимости с официальными скриптами установки на
[codex.sale/docs](https://codex.sale/docs) принимаются и их имена переменных:
`CODEX_SALE_API_KEY` (а также легаси `CODEX_LB_API_KEY`) для ключа и
`CODEX_SALE_BASE_URL` для базового URL. Приоритет — за именами `CODEXSALE_*`.

Ключ можно хранить и во встроенном хранилище учётных данных Pi, а не в
окружении:

```sh
pi auth check --provider codexsale
```

## Модели

Модели загружаются из `GET /v1/models` и преобразуются в модели Pi. Модель
попадает в список, только если она агентная:

- поддержка инструментов не отключена (если API не передаёт поле, считается,
  что она включена);
- `status`, если он присутствует, должен быть `active`;
- batch-варианты (идентификаторы, оканчивающиеся на `-batch`) исключаются;
- image-only модели (`gpt-image-*`, DALL·E, Flux и т. п.) исключаются, так как
  они не умеют вызывать инструменты.

Сейчас endpoint возвращает для каждой модели только `id`, `type`,
`display_name` и `created_at`. Если присутствуют более подробные поля, они
используются напрямую; иначе расширение берёт `context_window`, входные
модальности и уровни рассуждений из встроенного реестра и считает, что
поддержка инструментов есть. Поэтому новая модель, добавленная в API,
появляется в Pi автоматически, без правок расширения.

## Использование

```sh
pi --provider codexsale --model gpt-5.6-luna
pi --list-models codexsale
```

Уровни «мышления» доступны для моделей с поддержкой рассуждений. Сейчас API их
не сообщает, поэтому они берутся из встроенного реестра — например:

```sh
pi --provider codexsale --model gpt-6-astra:high
```

## Баланс

Codex Sale не предоставляет endpoint для кредитов и баланса, поэтому
расширение его не регистрирует и не отправляет подобных запросов при смене
модели. Баланс виден только в веб-интерфейсе Codex Sale. Тарификация идёт
расчётными токенами, а баланс общий для GPT и GLM.

## Заметки по устройству

- **Устойчивый разбор каталога.** Парсер принимает и плоский список `data[]`,
  который endpoint возвращает сегодня, и более богатую форму `models[]` с
  возможностями по каждому провайдеру, используя те поля, что есть.
- **Уровни рассуждений в обеих формах.** Принимаются `[{ effort: "high" }]` и
  `["high"]`.
- **Image-only модели отфильтровываются**, так как не умеют вызывать инструменты.

## Разработка

Шага сборки нет — Pi загружает исходники TypeScript напрямую (через jiti).

```sh
npm install        # ставит dev-зависимости и линкует типы peer-зависимостей Pi
npm run typecheck  # tsc --noEmit
```

Пакеты `@earendil-works/pi-ai` и `@earendil-works/pi-coding-agent`
предоставляются Pi во время выполнения, поэтому объявлены как необязательные
peer-зависимости и не ставятся из npm. `npm install` запускает
[`scripts/link-pi-types.mjs`](./scripts/link-pi-types.mjs), который
симлинкует их описания типов из установленного CLI `pi` в `node_modules`,
чтобы проверщик типов мог их найти. Задайте `PI_PACKAGE_ROOT` с путём к
каталогу `node_modules`, чтобы указать на другую установку Pi.
